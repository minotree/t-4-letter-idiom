# 6-3단계 API 비용 보호 및 사용량 원장

이번 단계의 실제 API 호출·이미지 생성은 모두 0입니다. `allow_live=false`를 유지합니다.
원본과 운영 manifest 695개를 보존하며 테스트는 임시 비용 원장과 가짜 응답만 사용합니다.

## 실제 호출 조건

유료 요청은 다음 조건을 모두 만족해야 합니다.

1. `config.toml`의 `allow_live=true`.
2. CLI `--live`.
3. CLI `--confirm-live`.
4. 유한한 양수 `--max-cost-usd`.
5. 양의 정수 `--max-api-calls`.
6. 프로세스 환경변수 `OPENAI_API_KEY`가 공백이 아닌 값으로 존재.
7. 현재 모델의 지원 사양, 가격 파일·유효기간·크기/품질 예약 프로필 검증 성공.

SDK 클라이언트가 테스트용으로 주입되어도 조건을 생략하지 않습니다.
실제 호출 직전에도 live 허용·키 존재·가격 유효성·원장·예산을 다시 검사합니다.
SDK 내부 재시도는 0이며 모든 요청 시도는 동일 게이트웨이를 거칩니다.
Mock은 별도 공급자를 사용하므로 실제 SDK와 운영 비용 원장을 사용하지 않습니다.

## 가격 파일과 예약 기준

`prices.json`은 정확한 모델 ID별 가격·공식 출처·확인 날짜와 예약용 토큰 가정을 담습니다.
확인일은 2026-10-20, 최대 유효기간은 30일입니다. 미래 날짜·기한 초과·알 수 없는 모델·변경된 파일·
없는 크기/품질 프로필·누락/음수/NaN 가격은 실제 호출을 차단합니다.
실행 중 가격 파일이 변경되어도 호출을 차단합니다. 자동으로 인터넷 가격을 가져오지 않습니다.

현재 일반 동기 요청의 공식 단가:

| 모델 | 입력 / 100만 토큰 | 출력 / 100만 토큰 |
| --- | ---: | ---: |
| gpt-4.1-mini | $0.40 (캐시 입력 $0.10) | $1.60 |
| gpt-image-2.5-flare-2026-09-08 | 텍스트 $5, 이미지 $8 | 이미지 $30 |

근거: [대본 모델](https://developers.openai.com/api/docs/models/gpt-4.1-mini),
[이미지 모델](https://developers.openai.com/api/docs/models/gpt-image-2.5-flare).
Images 직접 호출에는 캐시 할인 가정을 적용하지 않습니다.

예약용 가정은 청구 토큰 수와 구분합니다.

- 대본: 입력 4,000토큰, 출력 상한 2,200토큰 → 요청당 **$0.00512 예약**.
- 이미지: 현재 `1024x1536/medium`에 한해 입력 텍스트 4,000토큰, 이미지 출력 8,000토큰 가정 → **$0.26000 예약**.
- 숙어당 두 요청 합계: **$0.26512 예약**.

이미지 출력 8,000토큰은 운영자가 설정한 보수적 예측이며, 공식 고정 소비량이나 서버 출력 상한이 아닙니다.
입력은 직렬화된 요청 본문의 UTF-8 바이트 수에 512의 여유를 더한 로컬 검사를 통과해야 합니다.
이는 공식 토크나이저로 측정한 청구량이 아닙니다. 대본의 `max_output_tokens`도 예약 설정과 같아야 합니다.
다른 모델·품질·크기를 쓰려면 공식 가격과 해당 프로필을 검토·추가해야 합니다.

## 누적 예산과 예약 처리

`--max-cost-usd`는 이번 실행만의 추가 예산이 아니라 **동일 원장의 누적 예상 예산**입니다.
요청 전 `기존 예산 소모 + 이번 예약액 <= max-cost-usd`를 확인하고, 초과하면 원격 요청을 보내지 않습니다.
계산할 수 없는 요청도 차단합니다. 모든 재시도에 별도 예약액과 요청 ID가 필요합니다.

예산 소모액은 요청별 `max(예약액, 계산 가능한 사용량 비용 또는 수동 확인 비용)`의 누적 합입니다.
사용량 비용이 예상보다 낮아도 예약액을 자동 환급하지 않는 보수적 정책입니다.
이미 예약한 금액은 실행을 다시 시작하거나 예산 옵션을 다시 전달해도 사라지지 않습니다.
사용량 비용이 예약보다 크면 큰 값을 반영하며, 남은 예산이 음수일 수도 있습니다. 다음 호출은 차단됩니다.

**이 기능은 실제 결제 한도나 최종 청구 상한을 보장하지 않습니다.**
이미지 출력 토큰이 예측을 넘거나 응답을 잃으면 실제 청구액이 예약액과 다를 수 있습니다.
동일 원장을 사용하는 이 프로그램의 요청만 관리하며, 계정의 다른 앱·사용자 요청은 포함하지 않습니다.
가격 파일은 운영자가 확인하는 신뢰 설정이며, 공식 출처 URL 자체가 가격의 진실성을 자동 증명하지는 않습니다.

## 원장 저장과 복구

- 운영 원장: `data/api_usage_ledger.jsonl`.
- 마지막 이벤트 검증 표식: `data/api_usage_ledger.state.json`.
- 원장 단위 OS 잠금: 같은 경로를 사용하는 다른 프로세스는 전체 API 실행 중 진입할 수 없습니다.
- CLI에는 운영 원장 경로를 바꾸는 옵션이 없습니다. 테스트만 임시 원장을 주입합니다.
- 매 요청 전 `reserved` 이벤트를 기록하고 파일 flush/fsync 및 원자적 교체 후에만 전송합니다.
- 요청 후 결과 이벤트를 추가합니다. 각 JSONL 줄에는 순번·직전 해시·현재 해시가 있습니다.
- 기존 이벤트는 유지하며 전체 파일을 원자적으로 교체합니다. 상태 표식은 별도로 원자 교체합니다.
- 두 교체 사이에 중단되면 표식 불일치로 모든 추가 호출을 차단합니다. 자동 초기화·자동 복구하지 않습니다.
- 잘린 줄·잘못된 JSON·해시 불일치·중복 ID·불가능한 상태 전이·원장/표식 누락·꼬리 삭제를 차단합니다.

두 파일의 원자적 동시 트랜잭션을 보장하는 방식은 아닙니다. 대신 불일치를 발견하면 중단하는 정책입니다.
손상 시 파일을 보존·백업하고 실제 청구 내역 및 마지막 예약을 검토한 뒤 별도 복구해야 합니다.
원장을 지우거나 버전 관리의 빈 파일로 되돌리면 기록이 사라지므로, 운영 이후에는 별도 영속 백업이 필요합니다.
해시 연결은 손상 탐지용이며 파일을 임의로 재작성하는 공격자에 대한 전자서명은 아닙니다.

각 이벤트에 다음 항목이 있습니다.

- 로컬 `request_id`, `logical_id`, 숙어 ID, 모델, `request_type` (`script`/`image`).
- UTC 요청 시각·이벤트 시각, 상태·성공/실패 결과, 재시도 순번.
- 예상 예약 비용, 정제한 실제 토큰 사용량, 계산 가능한 사용량 비용.
- 제공업체 요청 ID가 반환되면 해당 ID, 오류 종류·HTTP 상태, 가격 확인일.

API 키·프롬프트 원문·응답 본문·SDK 예외 본문·스택 추적은 기록하지 않습니다.
동일 숙어·요청 유형·모델·본문을 해시한 논리 ID와 시도 순번으로 중복 요청을 막습니다.
성공 요청은 체크포인트 저장에 실패했더라도 원장에 있으면 자동 재요청하지 않습니다.
사용량 원장은 원격 API 요청의 성공/실패를 기록하며, 대본 의미·이미지 검수 성공을 뜻하지 않습니다.

## 비용 미확정과 재시도

응답을 받지 못했거나 필수 사용량이 없으면 `cost_unknown`으로 남깁니다.
예약만 남기고 프로세스가 종료된 `reserved`도 비용 미확정으로 취급합니다.
오류 응답에 사용량이 없다고 무료로 가정하지 않습니다.

성공 응답의 비용만 불명확하면 대본·그림 체크포인트 저장을 위해 응답은 반환하되, 다음 API 예약은 차단합니다.
타임아웃 등 응답이 없는 실패는 즉시 중단하며 자동 재시도하지 않습니다.
실패 응답의 토큰 사용량과 비용이 계산 가능한 경우에만 기존 재시도 정책과 남은 예산에 따라 재시도합니다.
일반적인 429/5xx에도 사용량이 없다면 미확정으로 멈추는 것이 현재 정책입니다.
동일 논리 요청의 시도 횟수는 원장에 남으므로 재시작해도 최대 3회 제한을 우회하지 않습니다.

청구를 사람이 확인한 뒤 API 없이 미확정 요청을 처리할 수 있습니다.

```powershell
# 아래는 형식 예시이며 실제 요청 ID·검증한 금액으로만 실행해야 함.
# --resolve-request REQUEST_ID --confirm-resolution --resolved-cost-usd AMOUNT --resolution-source billing-dashboard
```

`billing-dashboard` 또는 `provider-support` 확인 근거를 선택해야 하며 `--confirm-resolution`이 필요합니다.
0달러도 사람이 무과금을 확인했을 때만 입력합니다. 원래 예약은 유지하고 `resolved` 이벤트를 추가합니다.
손상된 원장은 이 옵션으로 우회할 수 없습니다. 원장의 구조 검증을 먼저 통과해야 합니다.
해결한 요청도 자동 중복 요청은 허용하지 않습니다.

## 비용 조회 (API·이미지 생성 없음)

```powershell
tools/image-generator/.venv/Scripts/python.exe tools/image-generator/generate.py --cost-report --limit 3 --max-cost-usd 2.40
```

보고 항목:

- 695개를 처음부터 제작할 전체 예약 예상액과 현재 선택 항목의 예약 예상액.
- 지금까지의 예약 합계, 토큰 사용량 기준 계산 비용, 수동 확인 비용.
- 비용 미확정 예약액·요청 ID, 누적 예산 소모, 남은 예상 예산.
- 원격 요청 성공·실패 수, 총 요청 수, 최대 시도 수를 적용한 선택 항목 예상액.

가격이 잘못되거나 오래되면 신규 예상액은 null과 오류 사유로 표시하고 종료 코드 1을 반환하지만,
검증 가능한 기존 원장의 예약·사용량 합계는 조회할 수 있습니다.
원장 자체가 손상되면 금액을 신뢰할 수 없으므로 보고도 중단합니다.
이 명령은 원장 내용을 수정하지 않으며 키도 필요하지 않습니다. 잠금용 임시 표식은 생길 수 있습니다.

## 3개 시험 제작에 필요한 예약 예산

| 조건 | 대본 예약 | 이미지 예약 | 총 예약 예산 |
| --- | ---: | ---: | ---: |
| 3개, 각 API 1회 | $0.01536 | $0.78000 | **$0.79536** |
| 3개, 두 API 각각 최대 3회 시도 | $0.04608 | $2.34000 | **$2.38608** |

기존 원장이 비어 있을 때 로컬 예약 계획은 재시도 없이 약 $0.80, 최대 시도 계획 약 $2.40입니다.
원장에 이미 소비한 비용이 있으면 그 금액을 더한 누적 예산을 지정해야 합니다.
이는 앞 단계의 일반적인 토큰 사용 가정에 따른 약 $0.201와 다른 **보호용 예약 계획**입니다.
실제 비용 추정이나 결제 한도로 혼동하면 안 됩니다.
695개를 처음부터 한 번씩 요청할 예약 예상액은 $184.25840입니다.
