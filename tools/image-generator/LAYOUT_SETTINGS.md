# V2 공통 설정 스키마 1 / 템플릿 1.0

이번 구현은 설정 로드·병합·검증만 제공합니다. 기존 합성기와 승인 함수는 수정하지 않았으며 새 설정을 사용하지 않습니다. `mode=settings_only`이고 `require_render_support()`는 항상 오류를 내므로 합성 연결이 구현된 것으로 간주하면 안 됩니다.

공통 파일: `templates/comic_v2/1.0.json`
모듈: `comic_engine/layout_settings.py`
향후 개별 파일 경로: `layouts/overrides/0002.json` 등. 이번에는 실제 ID 2 설정을 만들지 않았습니다.

## 병합 API와 규칙

```python
from comic_engine.layout_settings import resolve_settings, canonical_json

result = resolve_settings()  # 기본 설정 검증; 파일 저장 없음
# result = resolve_settings(override_path="검수한 개별 설정 경로")
settings = result["settings"]
layout_hash = result["sha256"]
serialized = canonical_json(settings)  # UTF-8 bytes, 정렬된 키, 2칸 들여쓰기, 끝 LF
```

- 객체는 키별 재귀 병합합니다. 생략한 값은 기본값을 유지합니다.
- 배열은 전체 교체합니다. 보호 영역 목록에 자동 추가하거나 인덱스로 병합하지 않습니다.
- `panels`는 배열이 아닌 `"1"`~`"4"` 키 객체입니다. 특정 컷의 일부 필드만 바꿀 수 있습니다.
- 미지 키, 필수 값 삭제, 잘못된 타입·좌표·버전, 중복 JSON 키, NaN/Infinity를 거부합니다. bool은 정수 좌표나 버전으로 허용하지 않습니다.
- 개별 설정은 `schema_version=1`, `template_version="1.0"`, 정규화된 문자열 `id`(1~695), 선택적 `panels`만 허용합니다. 버전은 기본 파일과 일치해야 합니다.
- ID는 반환값의 별도 필드입니다. SHA-256은 ID를 제외한 병합된 레이아웃 내용에 적용합니다. 향후 승인 연결 시 ID·원본·대본 해시도 함께 묶어야 합니다.
- 입력 객체를 변경하지 않으며, 같은 입력의 키 순서와 관계없이 같은 직렬화·해시를 만듭니다.

예외 설정 형식의 테스트는 임시 fixture에서만 수행합니다. 다음은 가상의 형식 설명입니다. 좌표를 실제 이미지의 검수값으로 사용하면 안 됩니다.

```json
{
  "schema_version": 1,
  "template_version": "1.0",
  "id": "2",
  "panels": {"2": {"bubble": {"width": 240}}}
}
```

## 지원 범위

기존 V2는 고정 폭의 말풍선 후보 탐색, 고정 방향 꼬리, 글꼴 측정·줄바꿈, 번호의 단일 위치, 한자 자동 폭·중앙 정렬, 보호 영역 검사를 지원합니다. 새 템플릿의 폭 후보·번호 위치 후보는 후속 구현용 정책 데이터이며 현재 합성기가 자동 선택하지 않습니다.

`speaker`는 null, `tail_direction`은 fixed_down_left만 허용합니다. 화자 추적·방향별 꼬리·자동 폭 선택·자동 번호 배치 플래그는 false만 허용합니다. 다른 값은 검증 단계에서 차단합니다. 이 제한은 기능이 실제 구현될 때 새 스키마/버전과 함께 확장해야 합니다.

기존 V2에 하드코딩된 512×1536, 4컷, contain 최대 508×380, 대사 20~23px, 말풍선 여백 12/10px, 한자 28~32px·좌우 여백 12px 등은 스키마에서도 고정 검증합니다. 품질·크기 정책은 설정으로 검증할 뿐 기존 config.toml이나 WebP 인코더에 적용하지 않습니다.

좌표는 출력 컷 내부 512×384 기준 정수입니다. 보호 사각형은 x1<x2, y1<y2이고 컷 내부여야 합니다. 말풍선 후보의 수평 범위·최소 높이와 번호 전체 영역도 검사합니다. 실제 대사 높이·그림 영역 포함 여부·의미 있는 배경과의 충돌 판정은 글꼴·원본이 필요한 후속 합성 단계의 책임입니다. 빈 보호 영역은 검수 완료를 뜻하지 않습니다. 충돌 시 needs_review, 자동 승인은 항상 false입니다.

## 기존 승인 결과 보존

`layouts/0001_v2.json`은 구형 합성기용 불변 설정입니다. 새 기본값을 병합하거나 ID 1에 소급 적용하지 않습니다. 신규 스키마는 구형 레이아웃 JSON과 구조가 다르며 직접 전달할 수 없습니다. 향후 명시적 어댑터·버전별 검증기·병합 스냅샷을 구현한 뒤 연결해야 합니다. 기존 승인 증빙의 설정 해시를 새 병합 해시로 바꾸면 안 됩니다.

기존 이미지·CSV·manifest·승인 증빙과 config.toml은 이 기능으로 수정되지 않습니다. API SDK나 네트워크를 호출하지 않습니다.
