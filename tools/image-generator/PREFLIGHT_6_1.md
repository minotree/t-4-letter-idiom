## API 요청 수

한 숙어의 4컷 그림 전체를 한 번에 요청합니다. 컷마다 API를 호출하는 구조가 아닙니다.
대본은 `responses.create` 1회, 그림은 `images.generate(n=1)` 1회입니다.
글자 합성·WebP 압축·글꼴 검사에는 API 호출이 없습니다.

| 제작 수 | 대본 요청 | 이미지 요청 | 합계 | 작업별 3회 시도 시 최대 대본/이미지/합계 |
| ---: | ---: | ---: | ---: | --- |
| 1 | 1 | 1 | 2 | 3 / 3 / 6 |
| 3 | 3 | 3 | 6 | 9 / 9 / 18 |
| 695 | 695 | 695 | 1390 | 2085 / 2085 / 4170 |

오른쪽은 한 실행에서 호출 제한을 충분히 높였을 때의 이론적 최대 시도 수입니다.
대본이 최종 실패하면 그 항목의 이미지 요청은 하지 않습니다. 유효한 체크포인트가 있으면
대본·그림 요청을 생략할 수 있습니다. 따라서 완료 수나 실제 청구 요청 수와 같다는 뜻이 아닙니다.

## 가격과 산식

USD 기준, 일반 동기 요청, 캐시 할인·Batch 할인·세금·환전·계정별 계약 가격 제외입니다.
실제 usage가 없으므로 아래 토큰 수는 측정값이 아닌 **계산 예시의 가정**입니다.

- 대본: 입력 1,000토큰, 출력 1,000토큰 (입력에는 지시문·숙어·스키마 등의 오버헤드 포함 가정).
- 이미지 프롬프트: 입력 텍스트 1,000토큰. 참조 이미지가 없는 신규 생성이므로 입력 이미지 토큰은 없음.
- 대본 가격: 입력 $0.40 / 100만 토큰, 출력 $1.60 / 100만 토큰.
- GPT Image 1 텍스트 입력: $5.00 / 100만 토큰.
- GPT Image 1 medium, 1024×1536 이미지 출력: 공식 표의 약 $0.063 / 장.
  이는 이미지 출력 비용이며 프롬프트 입력 비용을 별도로 더합니다.
  이미지 출력 토큰 가격을 다시 더하면 이중 계산이므로 더하지 않습니다.

```text
S = (0.40 × 대본 입력 토큰 + 1.60 × 대본 출력 토큰) / 1,000,000
I = 0.063 + 5.00 × 이미지 프롬프트 토큰 / 1,000,000
합계 = S + I

예시: S = $0.002, I = $0.068, 합계 = $0.070
```

근거: [대본 모델 가격](https://developers.openai.com/api/docs/models/gpt-4.1-mini),
[이미지 모델 가격](https://developers.openai.com/api/docs/models/gpt-image-1),
[이미지 비용 구성](https://developers.openai.com/api/docs/guides/image-generation#calculating-costs).
공식 장당 표의 반올림된 추정치를 사용했으므로 아래 소수점은 청구 정밀도를 의미하지 않습니다.

| 제작 수 | 대본 비용 | 이미지 출력 비용 | 이미지 프롬프트 비용 | 이미지 API 소계 | 전체 소계 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | $0.002 | $0.063 | $0.005 | $0.068 | $0.070 |
| 3 | $0.006 | $0.189 | $0.015 | $0.204 | $0.210 |
| 695 | $1.390 | $43.785 | $3.475 | $47.260 | $48.650 |

대본 출력이 코드 상한인 2,200토큰을 모두 사용하고 입력 가정은 동일하면 전체 비용 예시는
1개 $0.07192, 3개 $0.21576, 695개 $49.98440입니다.
이는 입력·이미지 프롬프트 토큰 수도 고정한 계산 예시이며 **보장된 최대 비용이 아닙니다**.

## 재시도·재생성 비용

현재 타임아웃·연결 오류·429·408·409·5xx는 재시도 대상입니다.
서버가 처리했으나 응답을 받지 못한 경우에는 다음 요청이 추가 과금될 수 있습니다.
각 실패 요청의 실제 과금 여부는 알 수 없으므로, 비용 보수 시나리오에서는 각 시도를 정상 1회만큼
청구한다고 가정합니다. 모든 오류가 실제로 과금된다는 단정은 아닙니다.

| 시나리오 | 1개 전체 | 3개 전체 | 695개 전체 |
| --- | ---: | ---: | ---: |
| 재시도 없음 | $0.070 | $0.210 | $48.650 |
| 두 작업 모두 3회 시도, 모든 시도 청구 가정 | $0.210 | $0.630 | $145.950 |
| 대본·그림을 새로 한 번 더 제작 (총 2회 제작) | $0.140 | $0.420 | $97.300 |
| 대본 재사용, 그림만 새로 한 번 더 제작 | $0.138 | $0.414 | $95.910 |

두 작업 모두 3회 시도할 때 이미지 API만의 비용 예시는 1개 $0.204, 3개 $0.612,
695개 $141.780이며 나머지는 대본 비용입니다.
반복 실행 횟수 자체에는 누적 상한이 없어, 위 3배 예시를 전체 제작 생애의 상한으로 볼 수 없습니다.
저장된 대본·그림을 재사용해 합성만 다시 하는 경우 추가 API 비용은 0입니다.
재생성 시나리오는 새 체크포인트/상태로 다시 요청하는 경우이며 현재 엔진이 검수 대기 항목을 자동 재제작하지는 않습니다.

## 크기·비율 및 잘림 위험

GPT Image 1은 `1024x1024`, `1024x1536`, `1536x1024`, `auto`를 지원합니다.
현재 1024×1536 (2:3)은 직접 지원하지만, 최종 512×1536 (1:3)은 직접 지원하지 않습니다.
원본 전체를 512×1536으로 단순 resize하면 가로만 반으로 줄어 인물이 눌리지만,
현재 구현은 그렇게 처리하지 않습니다.

`render.py`는 원본을 높이 기준으로 4등분하여 각 1024×384 영역을 꺼낸 다음,
`ImageOps.contain(..., (508, 202))`로 종횡비를 유지해 약 508×190~191로 줄입니다.
각 그림은 512×384 컷의 중앙 그림 영역에 놓고, 대사·정답·고지는 별도 영역에 합성합니다.
추가 cover crop이나 강제 가로·세로 비율 변경은 없습니다.

그러나 **모델이 정확히 같은 높이의 세로 4컷을 그린다는 보장은 없습니다**.
2×2 배열이나 불균등 높이로 출력하면 고정 4등분 경계에서 인물·장면이 잘릴 수 있습니다.
현재 엔진에는 실제 컷 경계/인물 위치 검출이 없으며, 빈 컷의 통계 검사만으로 이를 판정할 수 없습니다.
글자는 원본 그림과 분리해 합성하므로 그림을 가리지 않지만, 축소로 그림 디테일이 줄어드는 위험은 있습니다.
실제 시험 제작 후 컷 구조와 그림 디테일 검수가 필요하며, 이번 단계에서는 실이미지 품질을 검증하지 않았습니다.

## 비용 제한 안전성

**`--max-cost-usd`는 현재 구현되어 있지 않습니다.**
CLI 파서·설정·게이트웨이에 해당 옵션이나 금액 예산 로직이 없으므로 대본·이미지 어느 쪽에도 적용되지 않습니다.
이 옵션을 전달하면 argparse가 알 수 없는 인자로 거부합니다. 이번 점검에서는 기능을 추가하거나 있다고 가정하지 않았습니다.

현재 제공하는 보호:

- 기본 dry-run, `allow_live=false`, 명시적 `--live` 요구.
- `--limit`의 기본값은 1, `--ids`로 제작 대상을 제한.
- 필수 양수 `--max-api-calls`: 대본·이미지가 하나의 게이트웨이 카운터를 공유.
- 각 API 전송 직전에 카운터를 증가하므로 오류·재시도도 한도에 포함.
- SDK 내부 재시도는 0. 애플리케이션의 API 작업별 최대 시도 수는 3.
- 원자적 상태 저장·완료 및 검수 대기 항목 생략·단계별 체크포인트 재사용.

보장하지 못하는 사항:

- 달러 단위 상한, 실제 청구액, 프로세스 재시작을 포함한 누적 비용.
- 대본 응답 `usage`와 이미지 응답 `usage`를 비용 원장에 저장·환산하는 기능은 없음.
- 성공 응답의 usage를 기록하더라도 응답을 잃은 요청의 청구 비용까지 정확히 알 수는 없음.
- 타임아웃 시 서버의 작업 취소·무과금·중복 방지는 보장하지 않음.
- 프로세스가 재시작되면 호출 횟수 카운터도 0에서 시작. 다른 프로세스·앱의 계정 사용량은 포함하지 않음.
- 6회 호출 제한은 3개 완성이나 $0.210 이하를 뜻하지 않음. 재시도로 요청 배분과 비용이 달라질 수 있음.

금액 제한을 추가하려면 양쪽 API에 대한 보수적인 사전 비용 예약, 요청 토큰/출력 상한,
실사용량 반영, 응답 불명 시 예약 유지, 재시작 후 원장 복구, 가격 변경 감지가 필요합니다.
이 경우에도 로컬 예상 비용 한도와 제공업체의 실제 최종 청구 상한은 구분해 설명해야 합니다.

## API 키 및 현재 데이터

현재 실행 프로세스의 `OPENAI_API_KEY` 설정 여부: **false** (빈 값 포함).
키 값은 출력하거나 저장하지 않았고, `.env` 내용도 읽지 않았습니다.
엔진은 `.env`를 자동 로딩하지 않으므로, 파일에 키가 있어도 현재 환경변수가 없으면 사용할 수 없습니다.

원본 695개, 운영 manifest는 695개 모두 `pending`. 원본 CSV와 운영 manifest의 SHA-256은 직전 단계와 동일합니다.
운영 이미지 폴더의 WebP는 0개입니다. 이전 단계의 Mock 파일은 열거나 변경하지 않았습니다.

## 테스트와 실행한 명령

사용자의 후속 지시: **Mock을 포함해 이미지 생성 금지**.
따라서 기존 40개 테스트를 모두 발견하되, 이미지 생성 또는 이미지 파일명 fixture를 만드는 12개는
명시적으로 건너뛰었습니다. 나머지 28개 통과, 실패 0, 오류 0입니다.
**40개 모두 통과한 결과는 아닙니다.**

새 `run_no_image_tests.py`는 원본 테스트를 수정하지 않고 런타임 skip을 적용합니다.
Pillow 이미지 생성·읽기·저장과 socket/HTTP 전송에 차단 장치를 설치합니다.
금지 연산 시도는 0건이며, 건너뛴 테스트 목록은 `data/preflight_6_1_tests.json`에 있습니다.

```powershell
# 실제 실행한 안전한 재검증 명령 (보고서 경로는 새 파일이어야 함)
tools/image-generator/.venv/Scripts/python.exe tools/image-generator/run_no_image_tests.py --report data/preflight_6_1_tests.json
```

그 밖에 소스·설정·테스트를 읽는 명령, 키 존재 여부를 bool로 출력하는 명령,
공식 문서 검색/열람, Decimal 산술 계산을 수행했습니다. API 요청·이미지 제작 명령은 실행하지 않았습니다.

## 향후 실제 실행 명령 예시 — 이번 단계에서는 실행하지 않음

선행 조건: 모델 종료 문제 검토 및 필요 시 별도 모델 전환 검증, 비용 보호 보완,
계정 권한/결제 확인, 환경변수 설정, 실제 제작 승인.
그 뒤 설정에서 `allow_live=true`로 전환해야 아래 명령이 동작합니다.
현재 설정은 계속 false이며 키 설정·모델 교체·실제 실행은 하지 않았습니다.

```powershell
# 3개 시험 제작: 재시도 없는 정상 경로의 6회분만 허용
tools/image-generator/.venv/Scripts/python.exe tools/image-generator/generate.py --live --ids 1,2,3 --limit 3 --max-api-calls 6

# 전체 695개: 재시도 없는 정상 경로의 1390회분만 허용
tools/image-generator/.venv/Scripts/python.exe tools/image-generator/generate.py --live --limit 695 --max-api-calls 1390
```

재시도에도 예산이 소모되므로 위 요청 수로 모든 항목이 완성된다고 보장하지 않습니다.
새 모델로 변경하면 이 보고서의 GPT Image 1 비용 계산을 그대로 적용할 수 없으며 재산출해야 합니다.
