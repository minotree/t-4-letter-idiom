# ID 1 승인 결과 보존 기준

ID 1의 확정 기준은 `test_id1_preservation.py`의 고정 상수입니다. 실행 시 현재 파일에서 기대 해시를 다시 만들거나 새 기본값으로 재합성하지 않습니다. 테스트는 원본·CSV·manifest·증빙을 읽기만 하며, data 및 assets의 테스트 전후 파일 목록·해시도 비교합니다.

```powershell
# 프로젝트 루트에서: 실제 WebP 디코딩을 포함한 보존 검사
tools/image-generator/.venv/Scripts/python.exe -B -m unittest discover -s tools/image-generator -p test_id1_preservation.py -v

# 이미지 열기·생성을 금지하는 기존 회귀 검사
tools/image-generator/.venv/Scripts/python.exe -B tools/image-generator/run_no_image_tests.py
```

두 번째 명령은 보존 검사의 WebP 디코딩 테스트만 추가로 제외합니다. 해당 검사는 첫 번째 명령에서 실제 실행합니다. 기존 이미지 생성 관련 테스트 13개도 제외합니다.

## 고정할 증빙과 허용할 변화

- 정식 WebP와 승인된 미리보기: 확정 SHA-256 동일, WebP 512×1536 단일 프레임, 실제 디코딩 성공.
- CSV: UTF-8 BOM, 정해진 3열 헤더, 695행, ID 1 원문과 파일명 연결 유지. 다른 ID의 향후 정상 승인을 막지 않도록 전체 CSV 해시나 다른 행의 빈 파일명은 고정하지 않습니다.
- 두 manifest: 원본 순번 ID 1~695 유지, ID 1은 completed/approved. 다른 ID 상태는 고정하지 않습니다.
- 승인 증빙: ID·검수자·검수일·workflow와 출력·원본·보고서·대본·설정 해시, layout_version=2 및 render_revision=3을 고정합니다.
- 기존 ID 1 설정 파일과 검수 패킷은 불변 자료로 취급합니다. 새 공통 기본값은 별도 버전 파일로 추가해야 합니다.
- 현재 전역 트랜잭션은 ID 1 committed를 검사합니다. 다음 ID 승인으로 이 파일이 교체되기 전에 ID 1 트랜잭션의 불변 보관 경로를 추가하고, 같은 고정 증빙을 검사하도록 테스트를 확장해야 합니다. 이 요구 때문에 새 승인으로 테스트가 실패해도 기대값을 새 ID로 바꾸면 안 됩니다.

## 향후 템플릿 버전 공존의 통과 기준

1. 새 기본값·버전 추가 또는 변경 후에도 이 보존 테스트가 통과해야 합니다. 현재 테스트는 최신 renderer 버전 상수를 999로 바꾸어도 기존 증빙 검사가 변하지 않는지 확인합니다.
2. 검증기는 승인 증빙의 저장 버전으로 선택해야 합니다. 현재 `validate_v2()`는 최신 VERSION/RENDER_REVISION과 일치하도록 구현되어 있으므로 버전별 검증기 선택은 후속 구현 사항입니다. 이번 테스트 추가만으로 운영 검증기의 다중 버전 지원이 완성된 것은 아닙니다.
3. 기존 ID 1 승인 결과의 재검증·조회는 새 템플릿 기본값을 병합하거나 이미지를 재생성하지 않아야 합니다.
4. 새 템플릿의 설정·원본·대본·출력 해시는 새 증빙에 연결하고, 구버전 증빙과 바꿔치기하면 검증이 실패해야 합니다.
5. 같은 ID를 새 디자인으로 교체하는 작업은 별도 명시적 승인·백업·트랜잭션을 요구합니다. 기본값 변경만으로 기존 승인 결과를 교체하면 안 됩니다.

이번 단계에서는 승인 데이터, 템플릿, 운영 검증기를 수정하지 않습니다.
