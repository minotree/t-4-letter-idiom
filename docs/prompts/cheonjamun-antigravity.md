# Antigravity 작업 지시: 천자문 자료 생성

아래 지시 전체를 프로젝트 루트에서 실행 중인 Antigravity CLI에 붙여 넣으세요. 조사·파일 저장 기능이 실제로 가능한지 먼저 확인하게 합니다. 코딩·앱 통합 작업은 맡기지 않습니다.

---

이 프로젝트에 추가할 천자문 학습 자료의 초안을 만들어 주세요. 우선 루트 AGENTS.md의 조사·자료 검수 분담 원칙을 읽으세요. 이번 작업은 공개 자료 조사와 초안 작성입니다. 최종 검토·앱 반영은 Codex가 담당합니다.

## 목표와 범위

- 천자문을 원문 순서대로 네 한자씩 나눠 250개 구절로 정리합니다. 각 구절에 한글 독음과 한국어 뜻을 붙입니다.
- 기존 서비스는 글자 선택 → 후보 선택 → 선택한 후보의 독음 입력으로 진행합니다. 이번에는 자료만 준비하고 코드는 수정하지 마세요.
- 기존 한자성어와 천자문은 자료 종류가 다릅니다. 천자문 항목에는 category=cheonjamun을 사용합니다.
- 웹 접근·로컬 파일 읽기/쓰기를 실제로 할 수 있는지 확인하세요. 불가능한 기능은 가능하다고 주장하지 말고, 조사 가능한 범위와 부족한 부분을 보고하세요.

## 출처 조사

1. 기관·도서관·박물관·공개 고전 원문 등에서 천자문 전체를 확보하세요. 기준 판본의 이름·편자/역자(확인 가능한 범위)·제공 기관·URL·확인일을 기록하세요.
2. 기준 판본을 하나 정하고 독립된 다른 자료와 원문 순서·글자를 비교하세요. 한 사이트를 복제한 자료는 독립된 근거로 세지 마세요. 자료가 불일치하면 기준 판본 표기는 유지하고 이체자·판본 차이를 따로 기록하세요.
3. 독음은 한국 한자음으로 작성하고 두음법칙·별음·고전 문맥을 확인하세요. 모델 기억만으로 확정하지 마세요. 원문 근거와 독음/뜻 근거는 역할을 구분하세요.
4. 뜻은 앞뒤 구절의 문맥을 고려해 남녀노소 이해할 수 있는 한국어 한두 문장으로 직접 작성하세요. 현대 번역·해설을 대량 복사하지 마세요. 현대 독음/번역 자료의 이용 조건도 확인하고, 불명확하면 표시하세요. 고전 원문의 공개 여부만으로 현대 번역의 권리까지 해결됐다고 단정하지 마세요.
5. 원문 표시 한자를 일괄 NFKC 변환하거나 익숙한 글자로 치환하지 마세요. 검색용 정규화와 원문을 분리합니다. 반복 글자·이체자 발견은 보고하되 '1000자가 전부 서로 달라야 한다'는 가정으로 수정하지 마세요.
6. 출처를 읽지 못했으면 그 사실을 기록하세요. 검색 요약만 본 경우 본문 확인으로 표시하지 마세요. 근거가 없는 부분은 uncertain으로 남기고 URL·인용문·독음을 지어내지 마세요.

## 산출물

출력 디렉터리는 data/cheonjamun/draft/ 입니다. 디렉터리가 없으면 생성하세요. 동일 파일이 이미 있으면 덮어쓰지 말고 새 run-YYYYMMDD-HHMM 하위 디렉터리에 작성하고 경로를 알려 주세요. 전체 웹페이지나 책을 저장하지 말고 필요한 확인 정보와 허용 범위의 짧은 근거만 기록하세요.

### 1. cheonjamun.csv

UTF-8 CSV. 정확한 열 순서:

id,sequence,category,hanja,reading,meaning,source_ids,review_status,review_note

- id: cheonjamun-001부터 cheonjamun-250까지 안정적인 ID.
- sequence: 1부터 250까지 원문 순서.
- category: cheonjamun.
- hanja: 기준 판본의 네 한자. 구두점·공백은 별도 원문 근거에 남기고 필드에서는 제외.
- reading: 해당 구절의 한글 독음. 공백·설명은 넣지 말고, 독음 이견은 review_note에 기록.
- meaning: 구절의 문맥에 맞는 직접 작성한 한국어 풀이.
- source_ids: sources.json의 출처 ID를 세미콜론으로 연결. 근거가 적용되는 구절 범위를 명확하게 유지.
- review_status: draft 또는 uncertain. approved/검수완료는 사용하지 마세요.
- review_note: 근거 부족·별음·판본 차이·해석 주의 등. 이상 없으면 빈 값.

### 2. sources.json

각 출처에 id, title, institution_or_author, url, accessed_on, access_level(full_text/search_excerpt/unavailable), role(original/reading/meaning/cross_check), covered_sequences, edition, rights_note를 기록하세요. 검토를 재현할 수 있도록 확인한 권/쪽/절 또는 페이지 내부 위치도 locator에 남기세요. 없는 정보는 null로 둡니다.

### 3. review-notes.json

입력으로 사용한 기존 파일이 있으면 경로·SHA-256을 기록하세요. 새 CSV의 SHA-256도 기록하세요. 항목별 이견에는 id, original_value, proposed_value, decision(keep/change/uncertain), reason, source_ids, locator, checked_scope, unresolved를 포함하세요. 서로 다른 글자가 제시되는 경우 어느 판본에서 나온 것인지 구분하세요.

### 4. handoff.md

- 기준 판본·선정 이유·비교 자료·실제 조사 범위.
- 실제 생성 행 수·글자 수·누락·독음/뜻 미확인 항목.
- 판본 차이·표기 차이·해석 충돌·이용 조건.
- 다음 검토자가 볼 수정/불확실 항목 ID 목록.
- 모든 산출물의 상대 경로와 SHA-256.
- 출처 확인과 의미 판단의 한계. 초안임을 명시.

## 기계 검사와 작업 제한

- 가능한 경우 CSV 파서로 열·250행·sequence 연속성·ID 중복·네 한자/네 음절·필수 값·source_ids 참조 무결성을 검사하세요. 검사 명령과 실제 결과를 기록하고 미실행 검사를 통과로 쓰지 마세요.
- 누락된 구절을 추정해 채워 250행을 맞추지 마세요. 확보하지 못하면 부분 초안을 남기고 누락 sequence를 보고하세요.
- 루트 sajaseongeo_image_working.csv, 기존 data/ 자료, 앱 코드, AGENTS.md, progress.md를 수정하지 마세요. 이번 산출 디렉터리만 작성하세요.
- 설치·유료 서비스 결제·개인 계정 접근·비밀 정보 읽기·커밋·푸시·업로드·배포는 하지 마세요.
- 완료 시 긴 CSV 전체를 채팅에 출력하지 말고 기준 판본, 파일 경로, 완료/미확인 수, Codex 확인 대상만 간단히 보고하세요.
